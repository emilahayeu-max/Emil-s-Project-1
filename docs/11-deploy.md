# 11. Публикация приложения в интернет (GitHub Pages, бесплатно)

> Для новичка. Цель: получить обычную ссылку на приложение, которая открывается на любом устройстве — без предпросмотра Arena и без запуска на компьютере.

## Статус

- ✅ Статическая сборка приложения **уже собрана и загружена** в репозиторий (в корень ветки `arena/01a00135-emil-s-project-1`: папки `ru/`, `en/`, `_next/`, `icons/`, файлы `index.html`, `404.html`, `manifest.webmanifest`, `sw.js`).
- ✅ Ключи Supabase встроены в сборку при её создании (из `web/.env.local`, который в git не попадает).
- ⏳ Осталось **одно действие владельцу репозитория**: включить GitHub Pages (см. ниже). Робот-помощник не имеет на это прав.

## Как включить (5 кликов)

1. Откройте в браузере свой репозиторий: **https://github.com/emilahayeu-max/Emil-s-Project-1**
2. Вверху нажмите вкладку **«Settings»** (настройки)
3. В меню слева найдите и нажмите **«Pages»**
4. В блоке **«Build and deployment»**, строка **«Source»** — выберите **«Deploy from a branch»**
5. Ниже появятся два выпадающих списка:
   - **Branch**: выберите ветку **`arena/01a00135-emil-s-project-1`** (она в списке, просто может быть ниже `main`)
   - **Folder**: выберите **`/ (root)`** — корень
6. Нажмите **«Save»**

Через 1–2 минуты сайт станет доступен по адресу:

# 👉 https://emilahayeu-max.github.io/Emil-s-Project-1/ru/login

(На странице Settings → Pages после сохранения появится та же ссылка — по ней можно перейти прямо оттуда.)

## После публикации

- Приложение работает в **облачном режиме**: те же ключи Supabase, что и в предпросмотре. Аккаунты и записи — общие.
- Если при регистрации появляется «Проверьте почту» — подтвердите письмо от Supabase (папка «Спам»), либо в Supabase → Authentication → Sign In / Providers → Email выключите «Confirm email», и регистрация станет мгновенной.
- Обновление сайта: `cd web && node scripts/deploy-github-pages.mjs`, затем `git add -A && git commit && git push`. GitHub Pages пересоберёт сайт сам.

## Технические заметки

- `web/next.config.mjs`: `output: "export"` и `basePath` включаются только при `STATIC_EXPORT=1` / `NEXT_PUBLIC_BASE_PATH`. В предпросмотре и локально приложение работает как раньше (с серверным рендерингом).
- `/api/health` удалён: маршруты API невозможны в статической сборке. Проверку связи с облаком выполняет зелёная строка на экране входа.
- GitHub Pages сам подставляет `.html` к адресам страниц (pretty URLs), 404-страница перенаправляет на экран входа.
- Сервис-воркер и PWA-манифест работают с базовым путём `/Emil-s-Project-1`.

# 02. Техническое задание (ТЗ)

## 1. Общие сведения

| Поле | Значение |
|---|---|
| Рабочее название | **«Стоя» / Stoa** |
| Тип | Responsive web-приложение (mobile-first, работает на телефонах и ноутбуках) |
| Назначение | Стоический ежедневник: планирование дня, дневник, мотивационный гид, личные задачи |
| Цель проекта | Учебный / портфолио-проект с полным циклом разработки |
| Целевая платформа | Современные браузеры: Chrome/Safari/Firefox (последние 2 версии), Android/iOS WebView, Windows/macOS |
| Языки интерфейса | Русский, английский (переключение на лету, язык по умолчанию — из браузера) |
| Бюджет инфраструктуры | $0 (бесплатные тиры Supabase и Vercel) |

## 2. Цели и задачи системы

**Цель.** Дать пользователю единый ежедневный ритуал: утром настроиться и спланировать день, днём управлять задачами, вечером честно разобрать день — в духе стоической практики, с поддержкой контента (цитаты, практики, промпты) и приватным дневником.

**Задачи MVP:**
1. Регистрация/вход (email + пароль, OAuth Google) и восстановление пароля.
2. «Сегодня»: утренний ритуал (намерение дня, цитата дня, задачи), вечерний ритуал (разбор: что удалось, что вне контроля, урок, благодарность).
3. Дневник: записи (свободные и по промптам), настроение, теги, лента и просмотр по датам, редактирование/удаление.
4. Задачи: создание, приоритет, срок, метка «в моей власти / вне её», статусы (к выполнению / в работе / готово), повторяющиеся задачи, список на день.
5. Гид: библиотека практик (12 шт.) с шагами, цитаты дня, выполнение практики с привязкой к дневнику.
6. Прогресс: мягкий стрик ритуалов, статистика недели (без наказаний за пропуски).
7. Настройки: язык, тема (светлая/тёмная/системная), уведомления, экспорт данных (JSON/Markdown), удаление аккаунта.

**Задачи post-MVP (фаза 2):** PWA-установка и офлайн-режим, Web Push-уведомления, прикрепление изображений к записям, полнотекстовый поиск, экспорт в PDF, виджеты-цитаты, совместные «круги» (семья/команда).

## 3. Термины и определения

См. глоссарий в [00-brief.md](00-brief.md). Дополнительно:

| Термин | Определение |
|---|---|
| Цикл дня | Последовательность утренний ритуал → задачи дня → вечерний ритуал |
| Метка контроля | Атрибут задачи/рефлексии: `in_control` (в моей власти) / `external` (вне моей власти) — дихотомия Эпиктета |
| Сессия | Авторизованный период работы пользователя (Supabase Auth, JWT) |

## 7. Объём MVP и критерии завершения

**MVP включает** все требования с приоритетом M из раздела 4, NFR-1…NFR-4.

**Критерии завершения MVP (Definition of Done уровня релиза):**
- критический путь (регистрация → утренний ритуал → задача → вечерний ритуал → запись) проходит E2E-тест без ошибок;
- оба языка полны (0 пропущенных ключей), обе темы корректны;
- Lighthouse ≥ 90 (производительность, доступность, лучшие практики) на мобильном профиле;
- RLS-матрица подтверждена интеграционными тестами (пользователь не видит чужие данные);
- развёрнуто на Vercel + Supabase (продакшен-окружение), пройден чек-лист запуска из [09-build-plan.md](09-build-plan.md).

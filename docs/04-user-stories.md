# 04. Персоны, User Stories и Use Cases

## 1. Персоны

### Персона 1 — Артём, 27 лет, разработчик
- Живёт в большом городе, работает удалённо, телефон всегда под рукой, ноутбук — основной инструмент.
- Пробовал Todoist и Notion: задачи ведёт, но «смысловой слой» (зачем я это делаю) теряется.
- Знает стоицизм поверхностно (читал «Размышления» Марка Аврелия), хочет практики, а не лекций.
- **Боль:** вечером ощущение «день пролетел зря»; дневник бросал 5 раз.
- **Цель:** один инструмент «утром настроиться — вечером честно подвести итог».

### Персона 2 — Мария, 34 года, менеджер проектов
- Постоянный стресс: многое в работе вне её контроля, тревога из-за этого.
- Ведёт бумажный дневник, но несистемно; задачи — в телефоне, заметки — везде.
- **Боль:** переживает о вещах, на которые не влияет; нет привычки разбирать день.
- **Цель:** спокойнее относиться к неконтролируемому; видеть, что реально сделано.

### Персона 3 — Даниил, 21 год, студент (вторичная)
- Хочет дисциплину и мотивацию, чувствителен к «давлению» приложений (бросает всё, что виноватит за пропуски).
- **Боль:** прокрастинация; геймификация-наказание вызывает отторжение.
- **Цель:** мягкая структура дня без чувства вины; короткие вдохновляющие тексты.

## 4. Use Cases (сценарии использования)

### UC-01. Регистрация и вход
- **Актор:** новый пользователь. **Предусловие:** нет активной сессии.
- **Основной поток:** открывает приложение → «Начать» → email + пароль → письмо подтверждения → переход по ссылке → онбординг (3 шага) → экран «Сегодня».
- **Альтернативы:** A1 — email уже занят → сообщение и ссылка «Войти»; A2 — OAuth Google; A3 — письмо не пришло → повторная отправка; A4 — слабый пароль → подсказка требований.
- **Постусловие:** создан профиль, сессия активна.

### UC-02. Утренний ритуал (ключевой)
- **Актор:** Артём (авторизован). **Предусловие:** сегодняшний утренний ритуал не завершён.
- **Основной поток:** открывает «Сегодня» → видит цитату дня → пишет намерение → отвечает «что может помешать? как отвечу?» → выбирает 1–3 задачи на день (или создаёт новые) → «Завершить утро» → отметка в дневном логе, стрик обновлён.
- **Альтернативы:** A1 — пропускает поля (обязательно только намерение) → валидация мягкая, можно сохранить частично; A2 — нет задач → шаг пропускается; A3 — автозаполнение из вчерашних незакрытых задач (S).
- **Постусловие:** `day_log.morning_done = true`, задачи привязаны к дню.

### UC-03. Ведение задач в течение дня
- **Основной поток:** «Задачи» → создать («+») → название, приоритет, срок, метка контроля → сохранить → менять статусы по мере работы → вечером выполненные видны в итогах.
- **Альтернативы:** A1 — задача «вне моей власти» → появляется поле «как отвечу»; A2 — повторяющаяся задача → выбор правила повтора; A3 — канбан вместо списка.
- **Постусловие:** задача в БД, статусы синхронизированы между устройствами (Realtime).

### UC-04. Запись в дневник
- **Основной поток:** «Дневник» → «Новая запись» → текст (или «дайте промпт») → настроение, теги → сохранить.
- **Альтернативы:** A1 — запись из карточки практики (привязывается `practice_id`); A2 — черновик автосохраняется; A3 — редактирование/удаление старой записи.
- **Постусловие:** запись видна только владельцу (RLS).

### UC-05. Прохождение практики
- **Основной поток:** «Гид» → категория (например, «Принятие») → практика «Дихотомия контроля» → читает суть и шаги → «Выполнить» → пишет наблюдения → сохраняется в дневнике с меткой практики.
- **Альтернативы:** A1 — закрыл, не выполнив → практика остаётся в «не начато»; A2 — добавить в избранное.
- **Постусловие:** `practice_logs` запись, запись в дневнике связана.

### UC-06. Вечерний разбор
- **Основной поток:** вечером открывает «Сегодня» → блок «Вечер» → вопросы: что удалось? что было вне контроля? чему научился? за что благодарен? → автоитоги по задачам дня → сохранить → день закрыт, запись уходит в дневник.
- **Альтернативы:** A1 — вечер пропущен → назавтра мягкое приглашение «начать новый день», без упрёка.
- **Постусловие:** `day_log.evening_done = true`, создана запись типа `evening`.

### UC-07. Недельная сводка
- **Основной поток:** открывает «Прогресс» → видит стрик, счётчики недели, среднее настроение → возвращается к записям недели.
- **Постусловие:** сводка рассчитана из реальных данных (никаких «потерянных стриков»).

### UC-08. Переключение языка и темы
- **Основной поток:** «Настройки» → язык RU/EN → интерфейс и контент переключаются мгновенно (URL меняется на /ru, /en) → тема light/dark/system.
- **Постусловие:** выбор сохранён в профиле, применяется на всех устройствах.

### UC-09. Экспорт данных
- **Основной поток:** «Настройки» → «Экспорт» → генерация архива (записи, задачи, логи) в JSON + Markdown → скачивание.
- **Постусловие:** архив содержит все данные пользователя; операция ≤ 30 с.

### UC-10. Удаление аккаунта
- **Основной поток:** «Настройки» → «Удалить аккаунт» → предупреждение с перечислением последствий → повторный ввод email для подтверждения → каскадное удаление данных → выход.
- **Постусловие:** все строки пользователя удалены из БД (каскад), сессия завершена.

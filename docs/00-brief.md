# 00. Бриф и исходные ограничения

> Документ фиксирует решения, принятые на старте, чтобы вся команда (даже из одного человека 🙂) работала в одних рамках.

## 1. Идея продукта

Одно приложение «на каждый день», которое совмещает четыре роли:

1. **Стоический ежедневный планировщик** — утренняя подготовка к дню и вечерний разбор (структура из реальной стоической практики: Сенека «О гневе», Марк Аврелий «Размышления», Эпиктет «Энхиридион»).
2. **Мотивационный гид** — практики стоицизма (дихотомия контроля, негативная визуализация, memento mori, amor fati…), цитаты, короткие уроки.
3. **Личный дневник** — свободные записи + записи по промптам, с настроением и тегами.
4. **Менеджер личных задач** — задачи с приоритетами и особой стоической меткой: «в моей власти / вне моей власти».

Гипотеза продукта: *люди бросают дневники и планировщики, потому что те существуют отдельно друг от друга. Если один ритуал плавно перетекает в другой (утро → план → дела → вечерний разбор), привычка держится дольше.*

## 2. Зафиксированные решения (из брифа)

| Вопрос | Решение | Следствие |
|---|---|---|
| Хранение данных | **Сервер/облако** (аккаунт, БД, API, синхронизация телефон ↔ ноутбук) | Нужна регистрация, но пользователь не привязан к устройству |
| Бюджет | **$0** — только бесплатные тиры сервисов | Выбор стека ограничен бесплатными планами: Supabase, Vercel, GitHub и т.п. |
| Цель проекта | **Учебный / портфолио** | Полный цикл разработки, чистая архитектура, документация — важнее масштаба |
| Язык | **RU + EN** (i18n с первого дня) | Все строки интерфейса и весь контент (цитаты, промпты) — в двух языках |
| Технологический стек | На усмотрение разработчика | Обоснование — в [02-spec.md](02-spec.md) и [07-backend.md](07-backend.md) |
| Платформа | Responsive web (mobile-first), PWA — во 2-й фазе | Один код для телефона и ноутбука, установка «как приложение» позже |

## 3. Ограничения и допущения

1. **Бесплатный тир Supabase**: БД 500 МБ, 50 000 MAU (авторизация), хранилище файлов ~1 ГБ, проект «засыпает» после 7 дней неактивности. Для портфолио-проекта этого достаточно; риски и митигации — в [07-backend.md](07-backend.md).
2. **Приватность**: дневник — чувствительные данные. Защита на уровне БД (RLS), TLS, экспорт/удаление данных пользователем. Облачное хранение выбрано осознанно — ради синхронизации.
3. **Без нативной разработки**: только веб (HTML/CSS/JS). Уведомления — через Web Push / Notification API на этапе PWA.
4. **Контент**: цитаты и практики — переводы из первоисточников (Марк Аврелий, Сенека, Эпиктет) + собственные адаптации; не нарушаем авторские права.
5. **Один разработчик, гибкий график**: план сборки (09) рассчитан на 1 человека, этапы можно растягивать.

## 4. Рабочее название

**«Стоя» / Stoa** — в честь Расписной стои (Stoa Poikile) в Афинах, где Зенон Китийский основал школу стоиков около 300 г. до н. э. Название короткое, работает одинаково на русском и английском.

## 5. Глоссарий

| Термин | Значение |
|---|---|
| Утренний ритуал | Подготовка к дню: намерение дня, «что в моей власти», задачи, предвосхищение препятствий |
| Вечерний ритуал | Разбор дня: что сделано, что вне контроля, урок дня, благодарность |
| Дихотомия контроля | Принцип Эпиктета: часть вещей зависит от нас, часть — нет; метка задач и рефлексий |
| Практика | Короткое стоическое упражнение (негативная визуализация, amor fati, взгляд сверху…) |
| Промпт | Наводящий вопрос для записи в дневнике |
| Стрик | Серия дней подряд с выполненным ритуалом (показываем мягко, без чувства вины) |
| MoSCoW | Приоритизация: Must / Should / Could / Won't |
| RLS | Row Level Security — защита строк БД по владельцу |

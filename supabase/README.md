# Подключение Supabase (боевой режим, $0)

Полное обоснование выбора — [docs/07-backend.md](../docs/07-backend.md). Краткая инструкция:

## 1. Создание проекта (бесплатно)

1. [supabase.com](https://supabase.com) → New project (регион — ближайший к пользователям, например `eu-central-1`).
2. Скопировать из **Project Settings → API**:
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` key → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
3. Записать их в `web/.env.local` (см. [.env.example](../web/.env.example)). **Никогда** не коммитить ключи.

## 2. Применение миграций

Открыть **SQL Editor** в Supabase и выполнить по порядку:
1. [`migrations/0001_init.sql`](migrations/0001_init.sql) — таблицы, индексы, RLS-политики, авто-создание профиля;
2. [`seed.sql`](seed.sql) — контент: 12 цитат и 6 практик (полные версии контента живут в `web/src/lib/` — синхронизируйте при расширении).

## 3. Проверка RLS-матрицы (интеграционный тест IT-01/02)

1. Создать двух пользователей A и B (регистрация в приложении).
2. В SQL Editor от имени A: `select * from journal_entries;` → видно **только записи A**.
3. Анонимно (без сессии): запросы к `journal_entries`, `tasks`, `day_logs` возвращают пустые множества.
4. `quotes` и `practices` читаются любым авторизованным пользователем.

## 4. Риски бесплатного тира и митигация

| Риск | Решение |
|---|---|
| Проект «засыпает» после 7 дней неактивности | Cron-ping (GitHub Actions) каждые 3 дня; восстановление — кнопкой на дашборде |
| Нет бэкапов на Free | Экспорт данных из приложения («Ещё → Экспорт») + периодический скрипт |
| Лимит 500 МБ БД | Текстовая модель очень лёгкая: тысячи записей — копейки мегабайт |

## 5. Адаптер данных

Приложение уже спроектировано под переключение: `web/src/lib/store.tsx` — `LocalAdapter` (демо) заменяется на `SupabaseAdapter` при наличии env-ключей. Доменная логика (`lib/tasks.ts`, `lib/streak.ts`, `lib/quotes.ts`) не зависит от адаптера — она покрыта юнит-тестами.
